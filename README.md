# accounting
한국외국어대학교 노동조합 회계

## Firebase 설정

이 앱은 담당자 인증에 Firebase Authentication의 Google 로그인을, 공용 자료 저장에 Cloud Firestore를 사용합니다.

1. Firebase Console에서 **Authentication → 로그인 방법 → Google**을 사용 설정하고 Firestore 데이터베이스를 만듭니다.
2. **Authentication → 설정 → 승인된 도메인**에 배포된 사이트의 호스트명을 추가합니다. Google 로그인은 HTTPS 사이트에서 실행해야 합니다. `file://`로 직접 여는 방식은 지원하지 않습니다.
3. Firebase 웹 앱 설정을 [firebase-config.js](./firebase-config.js)에 둡니다. 웹 앱 설정은 공개 식별 정보이며, Admin SDK 서비스 계정 키나 비공개 키는 절대 넣지 마세요.
4. [firestore.rules](./firestore.rules)의 규칙을 **Firestore Database → 규칙**에 게시합니다.
5. 접근 허용은 **이메일 화이트리스트**로 관리합니다. Firestore에 `accessControl/allowedEmails` 문서를 만들고, 필드 `emails`에 **소문자** 이메일 배열을 넣습니다. 예: `{ "emails": ["user@example.com"] }`. Google 로그인 후 **이메일 인증이 완료된** 계정만, 이 목록에 있을 때 읽기·쓰기가 가능합니다. 목록 문서 자체는 콘솔에서만 수정할 수 있으며(규칙상 클라이언트 쓰기 불가), 앱에서는 등록된 사용자만 목록을 읽을 수 있습니다.

Firestore의 `accountingData` 컬렉션에 연도별 자료가 저장되고 브라우저 간 실시간으로 동기화됩니다. Firestore에 자료 문서가 없을 때 같은 브라우저의 이전 로컬 자료가 있으면 먼저 복사하고, 없으면 기본 자료를 초기화합니다. 기존 거래 내역의 관·항·목 분류도 자동으로 이전됩니다.

**사용자 관리** 탭에서 결산 담당자 이름을 추가하거나 삭제할 수 있고, 담당자별 은행명과 계좌번호를 따로 입력해 저장할 수 있습니다. 은행 정보는 모든 허가된 앱 사용자와 공유됩니다. 등록한 이름은 결산 관리의 담당자 입력란에서 드롭다운으로 선택할 수 있으며, 목록에 없는 이름도 직접 입력할 수 있습니다. 담당자 목록은 회계연도와 관계없이 공유되며, 목록에서 이름을 삭제해도 기존 거래 내역의 담당자 표기는 유지됩니다.

결산 내역 상태는 **입력완료 → 제출완료 → 승인**이며, 승인된 수입·지출 내역은 모두 같은 **승인** 상태로 표시됩니다. 입력완료에서는 선택한 한 건의 수정과 여러 건의 삭제가 가능하며, 수정·삭제는 제출 전에만 할 수 있습니다. 전체 내역의 승인된 거래는 **승인 취소**로 제출완료 상태에 되돌릴 수 있으며, 기존 가져온 거래도 취소하면 제출완료 대기 목록으로 돌아옵니다. 모든 허가된 로그인 사용자가 제출·반려·승인 처리를 할 수 있습니다. 한 번에 처리하는 내역의 담당자는 반드시 같은 한 사람이어야 하며, 여러 담당자의 내역을 함께 선택하면 결산 관리 화면에 빨간색 경고가 표시됩니다. 선택 입력완료 내역은 **선택 내역 제출**로 일괄 제출하고, Firestore 트랜잭션에서 관리번호를 중복 없이 발급해 장부 상태와 함께 저장합니다. 제출하면 해당 묶음에 회계연도를 넘어 1부터 계속 증가하는 관리번호를 부여하고, 승인 시 승인일(현지 날짜)과 당일 순번을 조합한 관리번호(예: `20261002001`)로 갱신합니다. 관리번호가 포함된 Firestore 문서 쓰기 권한이 허용되어야 하며, 권한이 거부되면 결산 화면에 안내가 표시됩니다. 보고서와 내역 목록에 현재 관리번호를 표시합니다. 입력완료·제출완료 내역은 보고서로 열람할 수 있으며, 지급신청서에는 관리번호를 제목 위의 별도 셀에 표시하고 성명·계좌·신청 정보·지출 목록을 연속된 단일 표로 구성합니다. 담당자의 등록된 은행명·계좌번호, 거래별 결제일·내역·지급처·금액·목, 합계와 영수증 첨부란을 표시합니다. 제출완료 내역을 승인하면 승인자와 승인 시각이 표시된 승인 도장이 포함된 PDF 한 개가 생성됩니다. 파일명은 `YYYYMMDD_담당자명_총액원.pdf` 형식입니다. 기존 `승인됨` 자료는 승인으로, 기존 `승인대기` 자료는 입력완료로 자동 이전됩니다.

새 내역 입력의 날짜 항목은 결제일로 표시합니다. `대학노조회비`는 새 내역의 세부 계정과목 선택 목록에서 제외됩니다.

결산 관리에서는 새 내역 입력이 입력 완료 처리 목록보다 먼저 표시됩니다. 지출 승인과 수입 승인은 모두 **승인**으로 표시하며 보고서 합계에 반영합니다. 모든 표의 제목과 금액이 아닌 셀 내용은 가운데 정렬하고 금액은 오른쪽 정렬합니다. 전체 내역 표는 페이지 스크롤에 따라 열람하며 제목 행은 상단에 고정됩니다. 보고서의 세부 거래 표는 결제일 열을 넓혀 날짜 전체가 표시되도록 합니다. 보고서의 예산 대비 실적·세부 거래·상위 지출 표에는 합계행을, 예산 관리의 분류표에는 수입·지출 예산 합계와 수입·지출 차액을 표시합니다.

관·항·목 기본 분류는 첨부된 분류표를 기준으로 복원하며, `대학노조회비`는 제외합니다. 기존 분류 데이터는 회계연도별로 한 번만 새 기본 분류로 이전하고, 일치하는 목 예산과 거래 분류는 새 경로로 보존합니다. 결제일은 날짜 형식으로 직접 입력하거나 달력에서 선택할 수 있습니다. 지급처·담당자·세부 계정과목은 최근 30일 사용 항목 중 최대 5개를 선택 목록 위에 우선 표시합니다.

공유 드라이브 PDF 저장을 사용하려면 Google Cloud Console에서 이 Firebase 프로젝트의 **Google Drive API**를 사용 설정하고, 승인하는 Google 계정에 공유 드라이브 대상 폴더의 파일 추가 권한을 부여하세요. 승인 시 Google Drive 파일 접근 권한 동의를 요청합니다. 저장 대상 폴더 ID는 앱의 `DRIVE_FOLDER_ID` 설정과 일치해야 합니다. PDF 생성에는 html2pdf.js CDN을 사용합니다.

예산 관리에서는 구분·관·항·목·예산을 한 표에서 행별로 관리합니다. 표 위에는 수입·지출 예산 합계와 차액을 표시하고, 수입 예산 합계는 수입 항목 마지막 행 아래에도 표시합니다. 표 내용은 가운데 정렬하며 금액은 오른쪽 정렬합니다. 전체 예산 차액은 수입 예산에서 지출 예산을 뺀 값이며, 차이가 있으면 빨간색으로 불일치를 표시하고 차이가 없으면 수입·지출 예산이 동일하다고 표시합니다. 예산 입력 금액은 천 단위 쉼표로 표시됩니다. 관·항 이름은 각각 `관`, `항`을 구분하는 접미사 없이 입력하며, 기존 이름 끝의 `_관`, `_항`은 자동 정리됩니다. 새 분류는 **목 추가**로 행을 만든 뒤 각 열을 입력하고 저장합니다. 예산은 회계연도별로 수입과 지출의 각 목에 입력하며, 새 회계연도에서는 **전년도 예산 불러오기**를 눌러 현재 분류와 일치하는 목의 금액을 채운 다음 변경 항목을 수정하고 **분류 및 예산 저장**을 눌러 저장합니다. 수입·지출 예산은 서로 구분해 저장하며, 보고서의 예산 대비 실적 표 위에는 수입·지출별 예산·결산 총액과 전체 예산 차액을 표시하고 표에는 예산 관리의 구분·관·항·목 순서대로 수입과 지출 목별 예산·집행액을 표시합니다. 기존 관별 예산 데이터가 있으면 초기 이전 시 소속 지출 목에 균등 배분하므로, 이전 안내가 표시되면 금액을 확인하고 조정하세요.


index.html이 data.json을 먼저 읽은 뒤 app.js를 실행합니다. data.json을 못 읽어도 빈 데이터로 앱은 동작합니다.
캐시 무효화는 `index.html`의 `window.APP_BUILD`와 `node stamp-version.mjs`로 처리합니다. 배포 전에 스탬프를 실행하면 `style.css`·`app.js`에 `?v=`가 자동으로 붙습니다.
index.html을 파일로 직접 열면 data.json을 읽지 못합니다. 자동완성 목록이 비게 되므로, Firebase Hosting 같은 서버에서 열어야 합니다. 로그인 기능도 서버 주소에서 열어야 동작하니 배포 환경에서는 문제없을 것입니다.
올려주신 파일 맨 위 <style>에 깨진 조각이 있어서 지웠습니다. 짝 없는 닫는 괄호와 "화면이 깨지면 괄호를 지워보세요"라는 메모, 모바일 전용 버튼 글자를 PC에서도 보이게 하는 규칙이 섞여 있었습니다. 버전 표시(.version-tag) 스타일은 유지했습니다.
app.js에 있던 myChartCanvas 차트 코드는 지웠습니다. 그 이름의 캔버스가 화면에 없어서 한 번도 실행되지 않던 코드입니다.
차트 범례·툴팁·높이

화면 폭 767px을 기준으로 4개 차트 모두 자동으로 바뀌고, 폰을 가로로 돌려 폭이 넘어가면 그 자리에서 다시 맞춰집니다.

범례: 모바일에서는 글자와 아이콘이 작아지고 위쪽 가운데로 옵니다. 지출 도넛은 우측 범례가 하단 범례로 바뀌고, 긴 이름은 12자까지만 보입니다. 전체 이름은 툴팁에서 확인할 수 있습니다.
툴팁: 모바일에서는 터치한 지점의 위쪽에 표시되어 손가락에 가려지지 않습니다. 긴 이름은 줄바꿈되고, 월별 차트는 한 번 터치로 수입과 지출이 함께 나옵니다.
높이 자동 조정: 모바일에서 도넛 차트는 범례 항목 수에 맞춰, 가로 막대 차트(수입 항목별, 예산 대비 집행)는 막대 수에 맞춰 차트 높이가 늘어납니다. 범례가 그래프를 누르거나 막대가 겹치는 일을 막기 위해서입니다.
축 눈금: 모바일에서는 금액이 1235만, 1.2억처럼 줄어들고, 가로 막대의 긴 이름은 9자까지 보입니다.
